# المعمارية وتدفق البيانات — سلّتي

## 1. الصورة الكاملة

```
 مواقع وتطبيقات المتاجر ──► Adapters (ملف مستقل لكل منصة/متجر)
 صفحات العروض (PDF/صور) ──► flyer_links ──► Vision LLM (تقطيع الصفحة إلى مربعات)
                                   │
                                   ▼
                    ┌──────────── قلب النظام (لا يتغيّر عند إضافة متجر) ────────────┐
                    │ 1. Normalizer: السعر → USD، قراءة الحجم (عربي/إنكليزي)، سعر الوحدة │
                    │ 2. Matcher: باركود ← (ماركة + وحدة + عدد العبوة + الحجم) ← تشابه الاسم │
                    │ 3. Validator (للكتالوجات): التواريخ، شكل العرض، نسبة الخصم          │
                    │ 4. Health: هبوط عدد المنتجات، فشل القراءة، تغيّر جماعي للأسعار       │
                    │ 5. Repository: Postgres/Supabase                                   │
                    └──────────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
            Supabase Postgres (PostGIS + pg_trgm) ── دوال RPC جاهزة للواجهة
                                   │
                                   ▼
        Next.js: /api/optimize ──► خوارزمية السلة والوقود (TypeScript) ──► الصفحات
```

**الجدولة:** GitHub Actions (`.github/workflows/scrape.yml`): الأسعار كل 6 ساعات، الكتالوجات يومياً.
كل تشغيل يُسجَّل في `scraper_runs`، والتنبيهات تُرسل إلى Slack/Discord/Telegram إن وُجدت مفاتيحها.

## 2. لماذا الـ Adapters تجعل إضافة متجر سهلة

العقد الوحيد بين المتجر والنظام هو `StoreAdapter` في `workers/pricewatch/adapters/base.py`:

| الدالة | ماذا تُرجع |
|---|---|
| `fetch_branches()` | الفروع مع الإحداثيات (اختياري) |
| `iter_listings()` | منتجات خام: اسم، سعر، عملة، حجم، باركود، فرع |
| `fetch_flyers()` | روابط ملفات العروض (اختياري) |

الـ Adapter **لا يحسب** شيئاً: لا تحويل عملة، لا مطابقة، لا كتابة في القاعدة. لذلك:

1. **متجر على منصة معروفة** (Shopify / WooCommerce / JSON API / HTML): سطر في `workers/config/stores.yaml` فقط.
2. **متجر بواجهة خاصة**: ملف واحد في `workers/plugins/` مع `@register_adapter("اسم")`. يُكتشف تلقائياً.
3. **حزمة خارجية**: عبر `entry_points` باسم `pricewatch.adapters`.

الأسرار تُكتب في الإعدادات بصيغة `${ENV_VAR}` وتُقرأ من البيئة وقت التشغيل، ولا تُحفظ في القاعدة.
للتجربة قبل التفعيل: `pricewatch try --store <slug> --limit 20` (بدون قاعدة بيانات).

## 3. الحماية من البيانات الخاطئة

| الخطر | الحماية |
|---|---|
| مقارنة كرتونة بقطعة | لا مطابقة إلا إذا تطابق **عدد العبوة** و**الحجم (±2%)** و**الوحدة** |
| منتج بلا حجم مقروء | لا يُطابق تلقائياً → `needs_review` |
| تغيّر تصميم موقع | `schema_drift` إذا فشل >20% من المنتجات |
| موقع يعرض جزءاً من المنتجات | `item_count_drop` إذا هبط العدد >40% عن المعتاد ← **لا تُحذف الأسعار القديمة** |
| تحويل الموقع من $ إلى ل.ل | `mass_price_change` إذا تغيّر >60% من الأسعار دفعة واحدة |
| خطأ قراءة الكتالوج | تحقق من التواريخ، الخصم ≤80%، مقارنة مع سعر السوق، ثقة النموذج ≥0.6، وإلا "بانتظار المراجعة" |
| دفع مرتين لقراءة نفس الكتالوج | بصمة SHA-256 للملف |
| مطابقة يدوية من الأدمن | `match_method = 'manual'` لا يُستبدل أبداً بالتشغيل التالي |

## 4. الرياضيات: السلة والوقود

لكل مجموعة فروع S يزورها المستخدم:

- **كلفة السلة:** `Basket(S) = Σ min_{b∈S} lineCost_b(item, qty)` — كل صنف من أرخص فرع داخل المجموعة.
- **كلفة السطر مع العروض:**
  - خصم سعر: `qty × min(shelf, promo)`
  - نسبة: `qty × shelf × (1 − p/100)`
  - "N بـ X": `⌊qty/N⌋ × X + (qty mod N) × shelf`
  - "اشترِ N واحصل على M": `(qty − ⌊qty/(N+M)⌋ × M) × shelf`
- **المسافة:** هافرساين `d = 2R·atan2(√a, √(1−a))` × معامل طرق 1.35 (طرقات لبنان متعرجة)،
  ويمكن استبداله بمصفوفة مسافات حقيقية (OSRM/Mapbox) عبر `options.distanceKm`.
- **المسار:** أقصر جولة البيت ← الفروع ← البيت، بالتجربة الكاملة لكل الترتيبات حتى 7 محطات.
- **الوقود:** `Fuel = km × (L/100km) ÷ 100 × (سعر الصفيحة ÷ 20)`.
- **عقوبة النقص:** `Penalty = Σ_missing median_price × qty × 1.25` (الصنف الناقص ليس مجانياً).
- **الهدف:** `J(S) = Basket + Fuel + Time + Penalty` ← الأصغر هو الأفضل.

**السيناريوهات:**
- **متجر واحد:** أصغر J بين كل الفروع ضمن النطاق.
- **تقسيم ذكي:** أصغر J لمجموعات من 2 إلى 3 فروع، بشرط ألا يزيد المسار أكثر من 12 كم عن خيار المتجر الواحد.
  يُعتبر "يستحق" فقط إذا وفّر ≥ 1$ بعد البنزين.
- **أقصى توفير:** نطاق أوسع ×1.5، محطة إضافية، ويزيد الكمية لأقرب حزمة عرض **فقط إذا كانت القطع الإضافية مجانية**.

**صافي التوفير** = (متوسط سعر السوق لنفس الأصناف + بنزين ذهاب وإياب لأقرب فرع) − (السلة + البنزين).

**الأداء:** البحث دقيق (كل التوافيق) حتى 25,000 مجموعة؛ بعدها خوارزمية جشعة + تبديل.
مثال حقيقي من الاختبارات: 9 فروع، 7 أصناف ← 384 مجموعة في ~30 ملي ثانية.
